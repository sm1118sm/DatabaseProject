# DB 정합성 보정 및 재검증 기록

검증 대상은 ERD, MySQL 테이블 구조, 함수 종속, SQL 데이터 검사이다. 화면·API 동작 검증은 이 문서의 범위에 포함하지 않는다.

## 수정 결과

2026-11-23 오후 2시 39분(KST)에 `defaultdb`의 두 불일치를 보정하고, 오후 2시 40분에 별도의 읽기 전용 트랜잭션으로 재검증하였다.

예약 시간대 전체 행 수는 수정 전·후 모두 50,409행이다. 해당 예약 시간대는 11월 3일~9일의 과거 시연 데이터였다. 기존 회원 잔액과 예약 금액·일시는 변경하지 않았다.

## 보정 절차

1. 잘못된 좌석 번호를 바로잡을 때 복합 기본키가 충돌하는지 확인하였다. 보정 대상 간 중복과 비대상 행과의 충돌은 모두 0건이었다.
2. 예약 및 관련 시간대 행과 시연 회원의 잔액·내역을 잠근 뒤 수정 전 원본을 로컬 파일로 백업하였다.
3. 트랜잭션 안에서 보정 대상 시간대 행만 올바른 좌석 번호로 교체하였다. 기본키의 교환 충돌을 피하기 위해 대상 행을 삭제·재삽입하되, 예약 번호와 시작 시간 및 총 행 수를 보존하였다.
4. 초기 지급 5,000P의 누락 내역을 추가하였다. 잔액을 줄이거나 기존 내역을 덮어쓰지 않았다.
5. 두 불일치가 0건이고 시간대 행 수와 회원 잔액이 보존됐는지 확인한 후 커밋하였다. 오류 시 전체 롤백하도록 처리하였다.
6. 커밋 이후 별도의 읽기 전용 SQL 검사로 전체 항목을 재확인하였다.

## 다시 검사하기

프로젝트 의존성을 설치하고 `.env` 또는 `ENV_FILE`에서 접속 설정을 읽는다. 원격 DB 연결은 서버 인증서를 검증하는 TLS 설정이 필요하다.

```powershell
$env:ENV_FILE = '.env.hosted'
npm run check:consistency -- --database defaultdb --output backups/consistency-check.json
```

읽기 전용 트랜잭션으로 검사하며, 불일치나 연결 오류가 있으면 종료 코드 1을 반환한다. 출력 파일은 `--output`을 지정할 때만 생성한다.

## 보정 스크립트

`scripts/repair-consistency-20261123.cjs`는 이번 과거 데이터 보정의 재현·감사 목적 스크립트이다. 서버 시작이나 Vercel 배포 과정에서는 자동으로 실행하지 않는다.

```powershell
# 기본 실행: DB에 연결하거나 수정하지 않고 사용법만 표시
node scripts/repair-consistency-20261123.cjs

# 명시적으로 요청할 때만 보정 시도
node scripts/repair-consistency-20261123.cjs --apply --database defaultdb
```

이미 정합한 상태이면 롤백 후 `alreadyConsistent`로 종료하여 보정 내역을 중복 추가하지 않는다. 보정이 필요한 경우 대상 49,560행·295건, 시연 계정과 누락 금액 5,000P, 과거 시간대 및 충돌 여부가 예상과 맞아야 진행한다. 다른 상태는 오류로 중단하며, 일반적인 자동 복구 도구로 사용하지 않는다.

기본 백업 위치는 `backups/consistency-20261123/<실행시각>/`이며 `.gitignore`에서 제외한다. `--backup-dir`로 다른 위치를 지정할 수도 있다.

## 시드 데이터의 누락 방지

`db/seed.sql`에서도 시연 회원의 초기 잔액을 생성한 직후 동일한 금액을 `point_history`에 기록하도록 수정하였다. 이는 새로 초기화하는 DB의 일관성을 위한 변경이다. 기존 DB에 시드 전체를 다시 실행할 필요는 없다.
